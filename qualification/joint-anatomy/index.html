Native CAD concept first

Placing a corner bracket with Forge

Goal: one short, readable Forge expression that tells SolidCraft exactly how a reusable corner bracket is attached — without raw direction vectors in normal model code and without a second orientation solver in Forge.

SolidCraft 0.30.1 · source commit 77050f5602feb8bfc39b4b04cb256b42bbdb06e6

1. Start with the real construction

The qualification use case is an open wooden frame. A neutral CornerBracket connects a side board to the top or bottom board.

4 brackets
One bracket at each side-to-top/bottom connection on the front edge.
8 brackets
Repeat exactly the same four connections at the rear edge.
Later: 3D corner
One true corner component on all eight corners of a box.
Front and rear are positions, not boards. There is no front or rear board in this relationship. They only identify which end of the cabinet depth receives the bracket.

Front view: the brackets are outside the wood frame

Depth view: four becomes eight

The bracket itself knows only its own local geometry. It does not know left/right, top/bottom, front/rear or the dimensions of the cabinet. The assembly chooses those placements.

2. Wat is een joint origin? / What is a joint origin?

Nederlands — eenvoudige uitleg

Een joint origin op een bracket (beugel) is het digitale ankerpunt waarmee je het onderdeel vastzet. Je kunt dit het beste zien als een klein lokaal assenstelsel met een eigen X-, Y- en Z-as.

  • Origin (het nulpunt): het precieze punt op de beugel waar het lokale assenstelsel begint, bijvoorbeeld het midden van een schroefgat.
  • Z-as (de normaal): bepaalt welke kant het bevestigingspunt op wijst.
  • X-as (de draaiing): zodra Z vastligt kan de beugel nog om Z draaien. X legt die klokstand vast.
  • Y-as (automatisch): zodra Z en X bekend zijn volgt de derde loodrechte as automatisch.
origin = waar zit het punt?
Z      = welke kant kijkt het punt op?
X      = hoe is het rond die richting gedraaid?
Y      = volgt automatisch

English — simple explanation

A joint origin on a bracket is the digital attachment point used to connect the part. The easiest way to understand it is as a small local coordinate system with its own X, Y and Z axes.

  • Origin: the exact point where the local coordinate system starts, for example the centre of a screw hole.
  • Z axis (normal): defines which way the attachment point faces.
  • X axis (clocking): once Z is fixed, X fixes the remaining rotation around Z.
  • Y axis (automatic): once Z and X are known, the third perpendicular axis follows automatically.
origin = where is the point?
Z      = which way does it face?
X      = how is it rotated around that direction?
Y      = calculated automatically

Conceptual API object

In a generic API the same local frame can be described explicitly with a point and two directions:

{
  "joint_origin": {
    "name": "beugel_bevestigingspunt_1",
    "description": "Midden van het bovenste schroefgat",
    "origin": {
      "x": 10.0,
      "y": 25.0,
      "z": 0.0
    },
    "axes": {
      "z_direction": [0, 0, 1],
      "x_direction": [1, 0, 0],
      "y_direction": "auto_calculated"
    }
  }
}

origin is the position. z_direction tells which way the local frame faces. x_direction fixes the remaining clocking around Z. Y does not need to be authored separately.

The same idea in Forge

For the six main axis directions, Forge uses readable names instead of requiring the vector every time:

ForgeVectorDirection
Anchor.RIGHT(1, 0, 0)+X
Anchor.LEFT(-1, 0, 0)-X
Anchor.BACK(0, 1, 0)+Y
Anchor.FRONT(0, -1, 0)-Y
Anchor.UP(0, 0, 1)+Z
Anchor.DOWN(0, 0, -1)-Z
 
AnchorFrame(
    origin=(10, 25, 0),
    z=Anchor.RIGHT,
    x=Anchor.UP,
)

These names are only readable unit vectors. They do not add a second orientation system. Arbitrary XYZ vectors remain valid for genuinely angled frames.

The real SolidCraft relationship remains explicit

Forge still lowers the frame to SolidCraft's own joint information. The readable names do not change the native data model.

A — frame side
edge + on + corner can select real topology. SolidCraft keeps that selection associated with changing geometry.
B — bracket side
point + z + x explicitly supplies the child joint origin and its orientation.

3. Where does the joint-origin frame come from?

Parent A: topology-backed

The frame side can use a real face/edge/corner. For an edge/corner origin SolidCraft derives its frame from the selected geometry and keeps the topology by name, so it can follow dimension changes.

Child B: explicit point frame

The current fixture chooses a point on the bracket and supplies z and x. If a point origin omits x, SolidCraft chooses x from z alone, so a part that was deliberately spun around z can turn back when joined.

Calling B a “local reference” is too vague. On this page we use the precise term child joint origin.

4. Zoom in: what do x and z mean at the four corners?

The current HUB75 model gives us a concrete example. The bracket geometry has its own model axes. The joint origin then defines another local frame on that geometry.

Do not mix these two coordinate systems. +X/+Y/+Z describe the bracket model. Lower-case joint x and z describe the frame SolidCraft uses to mate that bracket. For example, joint x = -Z means that the joint-frame x-axis points in the bracket model's negative-Z direction.

The two points used by the current HUB75 assembly

The reusable CornerBracket does not store these as named anchors. The assembly currently chooses two points on the neutral bracket geometry:

I = (0, 0, 0)          # inside corner / component origin
A = (0, 0, -w)         # one arm thickness below I
B = (w, 0, 0)          # one arm thickness right of I

For the front row, both A and B use the same current child-frame directions:

joint z = +Y = (0, 1, 0)     # out through the broad bracket face
joint x = -Z = (0, 0, -1)    # down along the bracket profile

For the rear row, the current assembly uses:

joint z = -Y = (0, -1, 0)    # opposite broad bracket face
joint x = +X = (1, 0, 0)     # right along the bracket profile

5. What the current Forge code is doing

The current fixture first defines the child joint origin in Python:

bracket_corner = AnchorFrame(
    origin=(0, 0, 0),
    z=Anchor.FRONT,
    x=Anchor.RIGHT,
)

and then uses it in the assembly:

bracket.copy().attach(
    frame,
    parent=Anchor.FRONT_TOP_LEFT,
    child=bracket_corner,
    angle=0,
)

The low-level vectors are still the real data, but ordinary model code no longer has to spell the six principal directions numerically. The readable constants make the intent visible while keeping the mapping to SolidCraft direct.

6. Requirements for the Forge API

  1. The generated data must map directly to SolidCraft's own joint-origin information. No second orientation solver in Python.
  2. CornerBracket must remain independent of the cabinet: no left/right, top/bottom, front/rear or cabinet dimensions.
  3. Forge must not guess orientation from a class name or from bracket geometry.
  4. Normal model code should not require raw vectors such as z=(0,-1,0) and x=(1,0,0).
  5. The low-level vector representation may remain available for genuinely low-level use.
  6. The solution is qualified first with four brackets, then eight, then a true 3D corner component.
Chosen API: keep AnchorFrame(origin, z, x), use the cardinal Anchor members as readable direction vectors, and keep arbitrary vectors available for non-axis-aligned frames. Forge does not guess any additional orientation.
